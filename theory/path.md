# Path

Path is the governed traversal across relations from intent to outcome.

Path says how work moves. Without Path, no action reaches completion.

## Definition

Path = the allowed route through the Fabric from intent to outcome.

A path is made of relations, gates, ports, and trust checks.

## Path flow

```
Actor
  ↓ relation
Role
  ↓ relation
Agent
  ↓ relation
Tool
  ↓ relation
Data / Device
  ↓ relation
Port
  ↓ relation
Exchange
  ↓ relation
Evidence
  ↓ relation
Trust update
```

## Path rules

- No path, no action
- No relation, no path
- No policy, no relation
- No trust, no traversal
- No evidence, no completion

## Path properties

- Every path must be declared
- Every path must be policy-approved
- Every path must be trust-calculated at each gate
- Every path must produce evidence at completion
- Every path must be revocable mid-traversal

## Path and Relation

Relation creates structure.
Path creates movement.

The Living Platform loop is a path across primitives:

```
Identity → Domain → Policy → Trust → Agent → Tool/Model/Data/Device → Port → Kube → OpenBox → Exchange → Evidence → Lifecycle
```
